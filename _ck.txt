checks/liftoff: 端到端验收（OVMF + ESP + 介质 → 内核 → PID 1）

- checks/liftoff/l1_boot_check.py：真实链路验收——OVMF 固件 → ESP 里的
  liftoff.efi → 介质（--medium iso|systemdisk）上的 /boot/kernel → 内核 →
  /programs/init.elf。断言全部取自串口实际输出，缺一即失败：
    [liftoff] M2b entry / Hello, BORUIX! / [boot] <mode> /
    [kmain] booting user init (PID 1) ... / [kmain] init: loaded /
    [kmain] init: spawned pid=1 from init.elf
  「看到 booting user init」不算数——成功分界行是 loaded 与 spawned。
- tools_build/liftoff.py：补 qemu_exe()（供 checks 直连 QEMU 用）。

实测（--medium systemdisk，规范系统盘）：5/6 → 6/6 锚全过，串口实录：
  [boot] install mode root = ... partition lba=2048 (EXT2)
  [kmain] init: loaded 54096 bytes of init.elf from /programs
  [kmain] init: entry=0x400000 stack_top=0x7ffefffffff0
  [kmain] init: spawned pid=1 from init.elf
即：liftoff 引导下 BORUIX 已经能拉起 PID 1。
