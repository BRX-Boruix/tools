fix(tools): --liftoff 的 ESP 改挂 USB 可移动介质（否则 OVMF 掉进 UEFI Shell）

症状（用户实测）：python main.py br --liftoff --release --serial --systemdisk --redisk
停在 UEFI Interactive Shell；不带 --systemdisk 时也进不去系统。

根因（OVMF BdsDxe 实录）：没有变量存储（未给 vars pflash）时，OVMF 只为**默认可移动
路径** EFI/BOOT/BOOTX64.EFI 建引导项。裸 IDE 挂载的 vvfat ESP 在多盘拓扑下拿不到
引导项——日志只有 Boot0001（系统盘，Not Found）与 Boot0003（Internal Shell），ESP 不在列。

修复（tools_build/liftoff.py::uefi_args）：
- 去掉 -boot order=c（强加 boot order 会让 OVMF 找不到引导项，直接进 Shell）；
- ESP 改为 USB 可移动介质：-drive if=none,id=liftoff-esp,format=raw,file=fat:rw:<esp>
  + -device qemu-xhci + -device usb-storage,drive=liftoff-esp。

实测（run --liftoff --serial --systemdisk --redisk）：
  BdsDxe: loading Boot0003 "UEFI QEMU QEMU USB HARDDRIVE ..." → starting
  [liftoff] M2b entry → M2C: mount ok → M2C: len=8011504 → Hello, BORUIX!
  [pmm] === LazyBuddy init: 28 memory-map entries ===
